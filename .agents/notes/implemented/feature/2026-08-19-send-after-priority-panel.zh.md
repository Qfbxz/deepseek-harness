# Agent Note：输入条尾行承载优先级胜者的上下文面板

Status: implemented

[English](2026-08-19-send-after-priority-panel.md) | 中文

## 问题

目标条、队列面板、todo 条各自作为独立全宽卡片堆叠在输入框下方的上下文 dock。会话进行中，目标——用户最需要看见的事实——位于输入行下方整整一个卡片高度；有目标在时队列与 todo 被完全推出视口折叠区。主发送按钮与卡片右缘之间的工具行是死余宽。

## 决策

新会话作用域列表 slot `conversation.input.send-after` 挂载在该尾座。三个面板注册进同一共享单元（`id: 'occupant'`），升序优先级——goalbar (5) > queue (10) > todo (15)——slot 渲染器只显示优先级胜者，行上至多一个面板，并随目标/队列/todo 的出现与消失沿链降级。InputBar 以 `flex: 1 1 0` 容器（`.sendAfter`）包裹 slot，长入行的剩余宽度；各面板 CSS 模块追加 `[data-send-after]` 属性桥规则去掉独立卡片宽度上限，同一 DOM 双模式渲染。dock 注册不动——面板落选时保留堆叠卡片挂载。

## 备选方案

- **三个并排尾座单元。** 三个面板同行宽会挤占发送按钮并迫使无关关注点间做宽度仲裁；单一胜者保持行的可读性，各面板的折叠行为仍是自己的决定。
- **为活动面板建 store。** 胜者可从注册优先级加目标/队列在场性推导——数据本就归条目所有。store 会复制该事实并需要跨三包的失效接线。
- **Portal 渲染逃出输入条。** 面板需要输入条的宽度约束来度量内容（目标文本对行余宽截断）；portal 得重新推导该约束。

## 影响

仅最高优先级的在场面板上行：有活动目标时队列与 todo 回落到 dock 卡片——正是用户表达的排序（运行中看目标；空闲看队列）。属性选择器桥（`[data-send-after]`）是唯一的跨模块 CSS 耦合，刻意用稳定属性而非他模块哈希类。slot 的 `priority` 语义是 slot 系统的标准排序字段，渲染器无需改动。

## 测试

`pnpm run test:gui`（client + host 包，272 文件 / 3757 测试）带功能挂载全绿；goalbar、queue、todo 套件钉住各自 dock 注册，会话骨架套件钉住含尾座的输入行渲染。
